Section A — React Fundamentals & JSX

The "what and why" of React. Interviewers often open with these.

1What is React? Why React?MUST KNOW
React is a JavaScript library (not a framework) for building fast, interactive user interfaces using a component-based architecture.
Key Points
  • Built by Facebook (Meta); uses a Virtual DOM for efficient UI updates.
  • Component-based: UI is broken into small, reusable, independent pieces.
  • Declarative: you describe what the UI should look like for a given state, React handles the how.
  • Used to build SPAs (Single Page Applications) — one HTML page, content updates dynamically without full reloads.
Interview Q&A
Q: Is React a framework or a library?
A: A library — it only handles the view layer (UI). Routing, state management, etc. come from separate libraries (React Router, Redux) that you choose and plug in yourself, unlike an opinionated framework like Angular.
Q: What problem does React solve?
A: Manually manipulating the DOM for complex, frequently-updating UIs is slow and error-prone. React lets you declare UI as a function of state, and efficiently updates only what changed.
2Virtual DOM & ReconciliationMUST KNOW
The Virtual DOM is a lightweight JS object representation of the real DOM kept in memory. Reconciliation is React's algorithm for comparing (diffing) the new Virtual DOM with the previous one and updating only the changed parts of the real DOM.
Key Points
  • Real DOM updates are slow; Virtual DOM diffing minimizes expensive direct DOM manipulation.
  • React uses a "diffing algorithm" to find the minimal set of changes needed.
  • The key prop helps React identify which list items changed/moved/were removed during reconciliation.
// When state changes, React:
// 1. Re-renders the component -> creates a new Virtual DOM tree
// 2. Diffs it against the previous Virtual DOM tree
// 3. Calculates the minimal set of real DOM changes
// 4. Applies ("commits") only those changes to the actual DOM
Interview Q&A
Q: Why is Virtual DOM faster than direct DOM manipulation?
A: Because comparing lightweight JS objects in memory is much cheaper than repeatedly triggering real browser reflow/repaint; React batches and applies only the minimal necessary real DOM changes at once.
3JSXMUST KNOW
JSX (JavaScript XML) is a syntax extension that lets you write HTML-like markup directly inside JavaScript. It gets compiled (via Babel) into React.createElement() calls.
Key Points
  • Must return a single root element (or use a Fragment <>...</>).
  • Use { } to embed JS expressions.
  • Use className instead of class, and camelCase for attributes like onClick, tabIndex.
const name = "Riya";
const element = (
  <div className="card">
    <h1>Hello, {name}!</h1>
    {name.length > 3 && <p>Long name</p>}
  </div>
);
// Compiles roughly to:
// React.createElement("div", {className:"card"}, ...)
Interview Q&A
Q: Is JSX required to use React?
A: No — it's optional syntactic sugar. You can write React.createElement() calls directly, but JSX is far more readable and is the standard convention.
Q: Why className instead of class?
A: Because "class" is a reserved keyword in JavaScript, so JSX uses className to avoid collision (it maps to the DOM's class attribute).
4Components & Functional ComponentsMUST KNOW
Components are independent, reusable pieces of UI. Modern React uses Functional Components (plain JS functions returning JSX) combined with Hooks, instead of the older Class Components.
function Welcome({ name }) {
  return <h1>Hello, {name}</h1>;
}
// or as an arrow function
const Welcome2 = ({ name }) => <h1>Hello, {name}</h1>;

// usage
<Welcome name="Riya" />
Interview Q&A
Q: Functional vs Class components?
A: Functional components are plain functions, use Hooks for state/lifecycle, and are simpler and shorter. Class components use ES6 classes, `this.state`, and lifecycle methods (componentDidMount, etc.). Functional + Hooks is now the standard.
Q: What are the rules for naming components?
A: Component names must start with a capital letter (PascalCase) so React can distinguish them from regular HTML tags.
5React Project SetupNEXT
Modern React apps are typically scaffolded with Vite (or Create React App historically) and use npm to manage dependencies listed in package.json.
Key Points
  • package.json — lists project dependencies, scripts, and metadata.
  • node_modules/ — where installed packages actually live (never edited manually, never committed to git).
  • createRoot(document.getElementById("root")).render(<App />) — the React 18+ way to mount your app into the DOM.
// main.jsx
import { createRoot } from "react-dom/client";
import App from "./App.jsx";

createRoot(document.getElementById("root")).render(<App />);

Section B — Components, Props & State

The daily bread-and-butter of React development. Expect live-coding questions here.

6PropsMUST KNOW
Props ("properties") are read-only data passed from a parent component to a child component, used to configure/customize it.
Key Points
  • Props are immutable inside the child — a child must never modify its own props.
  • children is a special prop containing whatever is nested between a component's opening/closing tags.
  • Default values can be set via default parameters in destructuring.
function Card({ title, children, theme = "light" }) {
  return (
    <div className={`card ${theme}`}>
      <h2>{title}</h2>
      {children}
    </div>
  );
}
// usage
<Card title="Profile">
  <p>This is child content</p>
</Card>
Interview Q&A
Q: Props vs State?
A: Props are passed IN from a parent and are read-only (external, immutable). State is managed WITHIN the component itself and can change over time (internal, mutable via setState/useState).
7State & useStateMUST KNOW
State is data local to a component that, when updated, triggers a re-render. useState is the Hook used to add state to functional components.
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);
  return (
    <button onClick={() => setCount(count + 1)}>
      Count: {count}
    </button>
  );
}
Key Points
  • useState(initialValue) returns [currentValue, setterFunction].
  • Calling the setter schedules a re-render; state updates are asynchronous (batched).
  • Use the functional update form when new state depends on old state: setCount(prev => prev + 1) — avoids stale-state bugs.
Interview Q&A
Q: Why use setCount(prev => prev + 1) instead of setCount(count + 1)?
A: React batches state updates, so multiple calls using the stale `count` variable in the same event handler can overwrite each other. The functional form always receives the latest state value, avoiding race conditions.
8State Immutability & Updating Nested DataMUST KNOW
React detects changes by comparing references, so state (objects/arrays) must always be updated by creating a new copy — never mutated directly — or React won't detect the change and re-render.
const [user, setUser] = useState({ name: "Riya", age: 22 });
// WRONG: user.age = 23; setUser(user);  -> same reference, no re-render!

// CORRECT:
setUser(prev => ({ ...prev, age: 23 }));

const [items, setItems] = useState([1, 2, 3]);
setItems(prev => [...prev, 4]);          // add
setItems(prev => prev.filter(i => i !== 2)); // remove
setItems(prev => prev.map(i => i === 1 ? 100 : i)); // update
Remember
  • Never do arr.push() or obj.x = y directly on state — always spread/copy first.
9Conditional RenderingMUST KNOW
Rendering different UI based on a condition, using plain JavaScript logic inside JSX.
function Status({ isLoggedIn, isLoading }) {
  if (isLoading) return <Spinner />;
  return (
    <div>
      {isLoggedIn ? <p>Welcome back!</p> : <p>Please log in</p>}
      {isLoggedIn && <LogoutButton />}
    </div>
  );
}
Interview Q&A
Q: Any gotcha with the && operator in JSX?
A: If the left side is 0 (a falsy number, not boolean), React renders the literal "0" on screen instead of nothing. Fix: convert to boolean, e.g. count > 0 && ..., or use a ternary.
10Lists, Keys & Rendering ArraysMUST KNOW
Rendering a list of elements from an array using .map(). Each rendered item needs a unique key prop so React can efficiently track it during reconciliation.
const users = [{id:1, name:"A"}, {id:2, name:"B"}];
<ul>
  {users.map(user => (
    <li key={user.id}>{user.name}</li>
  ))}
</ul>
Interview Q&A
Q: Why should you avoid using array index as key?
A: If items are reordered, inserted, or removed, index-based keys don't stay tied to the same item, causing React to misidentify elements — leading to incorrect UI state, broken animations, or unnecessary re-renders. Use a stable unique ID instead.
11Events & Event ObjectMUST KNOW
React wraps native DOM events into a cross-browser SyntheticEvent object, accessed via camelCase handler props like onClick, onChange.
function Form() {
  function handleSubmit(e) {
    e.preventDefault(); // stop page reload
    console.log("Submitted");
  }
  function handleClick(id, e) {
    console.log("Clicked item", id, e.target);
  }
  return (
    <form onSubmit={handleSubmit}>
      <button onClick={(e) => handleClick(1, e)}>Click</button>
    </form>
  );
}
Interview Q&A
Q: How do you pass arguments to an event handler?
A: Wrap the call in an inline arrow function: onClick={() => handleClick(id)} — calling handleClick(id) directly would invoke it immediately during render instead of on click.
12Forms & Controlled ComponentsMUST KNOW
A "controlled component" is a form input whose value is driven entirely by React state — the input's value comes from state, and onChange updates that state, making React the "single source of truth".
function LoginForm() {
  const [form, setForm] = useState({ email: "", password: "" });

  function handleChange(e) {
    const { name, value } = e.target;
    setForm(prev => ({ ...prev, [name]: value }));
  }
  function handleSubmit(e) {
    e.preventDefault();
    console.log(form);
  }
  return (
    <form onSubmit={handleSubmit}>
      <input name="email" value={form.email} onChange={handleChange} />
      <input name="password" type="password" value={form.password} onChange={handleChange} />
      <button type="submit">Login</button>
    </form>
  );
}
Interview Q&A
Q: Controlled vs Uncontrolled components?
A: Controlled components store input value in React state (React is source of truth, full control/validation). Uncontrolled components let the DOM manage its own state internally, accessed via a ref (e.g. useRef) only when needed — less code but less control.

Section C — Hooks Deep Dive

Hooks questions are almost guaranteed in every React interview. useEffect and useState get asked the most.

13Rules of HooksMUST KNOW
Two strict rules that ensure Hooks work correctly, because React relies on the call order of Hooks to associate state with a component instance.
Key Points
  • Rule 1: Only call Hooks at the top level — never inside loops, conditions, or nested functions.
  • Rule 2: Only call Hooks from React function components or custom Hooks — never regular JS functions.
// WRONG
if (isLoggedIn) {
  const [data, setData] = useState(null); // breaks hook order!
}

// CORRECT
const [data, setData] = useState(null);
if (isLoggedIn) { /* use data */ }
Interview Q&A
Q: Why can't hooks be called conditionally?
A: React tracks hooks by the order they're called in, across renders. Calling one conditionally can shift that order between renders, causing React to associate the wrong state/effect with the wrong hook call.
14useEffectMUST KNOW
A Hook for running side effects (data fetching, subscriptions, timers, manual DOM changes) in function components — it replaces class lifecycle methods like componentDidMount/Update/Unmount.
Key Points
  • useEffect(fn) — no deps array → runs after every render.
  • useEffect(fn, []) — empty array → runs once on mount only.
  • useEffect(fn, [dep1, dep2]) — runs on mount + whenever any dependency changes.
  • Return a cleanup function to unsubscribe/clear timers before the effect re-runs or the component unmounts.
useEffect(() => {
  const timer = setInterval(() => console.log("tick"), 1000);
  return () => clearInterval(timer); // cleanup
}, []);

// API call pattern
useEffect(() => {
  let ignore = false;
  async function loadUser() {
    setLoading(true);
    try {
      const res = await fetch(`/api/users/${id}`);
      const data = await res.json();
      if (!ignore) setUser(data);
    } catch (e) {
      if (!ignore) setError(e.message);
    } finally {
      if (!ignore) setLoading(false);
    }
  }
  loadUser();
  return () => { ignore = true; }; // avoid setting state after unmount
}, [id]);
Interview Q&A
Q: What causes an infinite loop with useEffect?
A: Updating state inside the effect without a proper dependency array (or including an object/array/function recreated fresh every render as a dependency) causes the effect to re-run after every render, updating state again, forever.
Q: Why is a cleanup function important?
A: Without it, timers, subscriptions, or event listeners from a previous render/mount keep running even after the component unmounts or the effect re-runs — causing memory leaks and "setState on unmounted component" warnings.
15useRefMUST KNOW
Returns a mutable ref object ({ current: ... }) that persists across renders without causing a re-render when changed. Commonly used to directly access DOM elements.
function TextInput() {
  const inputRef = useRef(null);
  function focusInput() { inputRef.current.focus(); }
  return (
    <>
      <input ref={inputRef} />
      <button onClick={focusInput}>Focus</button>
    </>
  );
}

// storing a mutable value that doesn't trigger re-render
function Timer() {
  const countRef = useRef(0);
  useEffect(() => {
    const id = setInterval(() => { countRef.current++; }, 1000);
    return () => clearInterval(id);
  }, []);
}
Interview Q&A
Q: useRef vs useState?
A: Updating state (useState) triggers a re-render; updating a ref (useRef) does NOT trigger a re-render and persists silently across renders. Use state for anything shown in the UI, refs for values you need to track without re-rendering (timers, previous values, DOM nodes).
16useReducerNEXT
An alternative to useState for managing more complex state logic — especially when the next state depends on multiple sub-values or the previous state, following a Redux-like pattern.
function reducer(state, action) {
  switch (action.type) {
    case "increment": return { count: state.count + 1 };
    case "decrement": return { count: state.count - 1 };
    case "reset": return { count: 0 };
    default: throw new Error("Unknown action");
  }
}

function Counter() {
  const [state, dispatch] = useReducer(reducer, { count: 0 });
  return (
    <>
      <p>{state.count}</p>
      <button onClick={() => dispatch({ type: "increment" })}>+</button>
      <button onClick={() => dispatch({ type: "decrement" })}>-</button>
    </>
  );
}
Interview Q&A
Q: When would you use useReducer over useState?
A: When state has multiple related sub-values, complex update logic, or the next state depends heavily on the action type — useReducer centralizes that logic and makes state transitions more predictable/testable.
17useMemo & useCallbackNEXT
Both are memoization hooks used for performance optimization. useMemo memoizes a computed value; useCallback memoizes a function reference.
const expensiveResult = useMemo(() => {
  return heavyComputation(items);
}, [items]); // only recompute when items changes

const handleClick = useCallback(() => {
  doSomething(id);
}, [id]); // same function reference unless id changes
Interview Q&A
Q: useMemo vs useCallback?
A: useMemo caches the RESULT of a computation. useCallback caches the FUNCTION itself (equivalent to useMemo(() => fn, deps)). Both are used to avoid unnecessary recalculation/re-creation on every render, and to prevent unnecessary re-renders of memoized child components.
Q: Should you use useMemo everywhere for optimization?
A: No — memoization itself has a cost (memory + comparison). Only use it for genuinely expensive computations or to stabilize references passed to memoized children/effects; overusing it can make code slower and harder to read.
18Custom HooksMUST KNOW
A custom Hook is a reusable JavaScript function (prefixed with use) that packages up stateful logic (usually built from other Hooks) so it can be shared across multiple components.
function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    setLoading(true);
    fetch(url)
      .then(res => res.json())
      .then(setData)
      .catch(setError)
      .finally(() => setLoading(false));
  }, [url]);

  return { data, loading, error };
}

// usage in any component
function Profile() {
  const { data, loading, error } = useFetch("/api/profile");
  if (loading) return <Spinner />;
  if (error) return <p>Error!</p>;
  return <p>{data.name}</p>;
}
Interview Q&A
Q: Why build custom hooks?
A: To extract and reuse stateful logic (like data fetching, form handling, debouncing) across multiple components without duplicating code, keeping components focused purely on rendering UI.

Section D — Component Communication & State Management

How data flows across a React app as it grows beyond a single component.

19Prop Drilling & Lifting State UpMUST KNOW
Lifting state up means moving shared state to the closest common parent so sibling components can access/update it via props. Prop drilling is the resulting problem of passing props down through many intermediate components that don't need them.
function Parent() {
  const [count, setCount] = useState(0);
  return (
    <>
      <DisplayCount count={count} />
      <IncrementButton onIncrement={() => setCount(c => c + 1)} />
    </>
  );
}
// Child -> Parent communication via a callback prop
function IncrementButton({ onIncrement }) {
  return <button onClick={onIncrement}>+1</button>;
}
Interview Q&A
Q: How do child components communicate back to a parent?
A: The parent passes a callback function down as a prop; the child calls that function (optionally with data) when something happens, and the parent updates its own state in response.
Q: How do you fix prop drilling?
A: Use the Context API to make data available directly to deeply nested components without passing it through every intermediate layer, or use a state management library like Redux for larger apps.
20Context APIMUST KNOW
A built-in React feature to share data (like theme, auth user, language) across the component tree without manually passing props at every level.
const ThemeContext = createContext();

function App() {
  const [theme, setTheme] = useState("light");
  return (
    <ThemeContext.Provider value={{ theme, setTheme }}>
      <Toolbar />
    </ThemeContext.Provider>
  );
}

function Toolbar() {
  const { theme, setTheme } = useContext(ThemeContext);
  return (
    <button onClick={() => setTheme(theme === "light" ? "dark" : "light")}>
      Current: {theme}
    </button>
  );
}
Interview Q&A
Q: Context API vs Redux?
A: Context API is built into React, best for simple/low-frequency global data (theme, auth user, locale). Redux is a dedicated external state management library with predictable update patterns, middleware, and devtools — better suited for large apps with complex, frequently-updating shared state.
Q: Any downside of Context API?
A: Every component consuming a context re-renders whenever the context value changes, even if it only cares about part of that value — this can cause unnecessary re-renders in large apps if not split carefully.
21Redux & Redux ToolkitNEXT
Redux is a predictable state container: a single centralized store holds app state, updated only via dispatched actions processed by pure reducer functions. Redux Toolkit (RTK) is the modern, recommended way to write Redux with much less boilerplate.
Key Points
  • Store: holds the whole app's state tree.
  • Action: a plain object describing "what happened" ({type, payload}).
  • Reducer: a pure function (state, action) => newState.
  • createSlice() — RTK helper that auto-generates action creators + reducer.
  • useSelector() reads state; useDispatch() sends actions.
// counterSlice.js
import { createSlice } from "@reduxjs/toolkit";

const counterSlice = createSlice({
  name: "counter",
  initialState: { value: 0 },
  reducers: {
    increment: (state) => { state.value += 1; }, // RTK allows "mutating" syntax (uses Immer internally)
    decrement: (state) => { state.value -= 1; },
  },
});
export const { increment, decrement } = counterSlice.actions;
export default counterSlice.reducer;

// in a component
const count = useSelector((state) => state.counter.value);
const dispatch = useDispatch();
dispatch(increment());
Interview Q&A
Q: What is Redux Thunk used for?
A: Middleware that lets action creators return a function (instead of a plain object) to handle async logic like API calls, dispatching further actions once the async work resolves.

Section E — Routing

React Router is the standard for multi-page navigation in an SPA.

22React Router EssentialsMUST KNOW
A library that enables client-side navigation between different "pages" (views) within a Single Page Application, without full browser reloads.
import { BrowserRouter, Routes, Route, Link, useNavigate } from "react-router-dom";

function App() {
  return (
    <BrowserRouter>
      <Link to="/about">About</Link>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
        <Route path="*" element={<NotFound />} />  {/* 404 */}
      </Routes>
    </BrowserRouter>
  );
}

function LoginButton() {
  const navigate = useNavigate();
  return <button onClick={() => navigate("/dashboard")}>Login</button>;
}
Interview Q&A
Q: Link vs useNavigate?
A: Link renders an anchor tag for declarative, user-clickable navigation. useNavigate is a hook for programmatic navigation triggered by code (e.g. after form submit or a conditional check).
Q: NavLink vs Link?
A: NavLink is the same as Link but automatically adds an "active" styling/class when its path matches the current URL — useful for nav bars.
23Dynamic & Nested RoutesMUST KNOW
Dynamic routes capture URL segments as parameters (via useParams); nested routes render child routes inside a parent layout using <Outlet />.
<Route path="/users/:id" element={<UserProfile />} />

function UserProfile() {
  const { id } = useParams();          // dynamic route param
  const [searchParams] = useSearchParams(); // ?query=... params
  return <p>User ID: {id}</p>;
}

// Nested routes
<Route path="/dashboard" element={<DashboardLayout />}>
  <Route path="stats" element={<Stats />} />
  <Route path="settings" element={<Settings />} />
</Route>
// DashboardLayout must render <Outlet /> where child routes appear
24Protected RoutesMUST KNOW
A pattern that restricts access to certain routes based on authentication state — redirecting unauthenticated users to a login page.
function ProtectedRoute({ children }) {
  const { isAuthenticated } = useAuth(); // custom hook/context
  if (!isAuthenticated) return <Navigate to="/login" replace />;
  return children;
}

<Route path="/dashboard" element={
  <ProtectedRoute><Dashboard /></ProtectedRoute>
} />

Section F — API Integration & Authentication

Almost every real-world React app talks to a backend — expect practical questions here.

25Fetch / Axios & HTTP MethodsMUST KNOW
Making HTTP requests to a REST API using the native fetch() or the popular axios library, using standard HTTP methods (GET, POST, PUT, PATCH, DELETE).
// fetch
async function getUsers() {
  const res = await fetch("/api/users");
  if (!res.ok) throw new Error("Failed to fetch");
  return res.json();
}

// axios (auto JSON parsing, throws on non-2xx by default)
import axios from "axios";
const { data } = await axios.get("/api/users");
await axios.post("/api/users", { name: "Riya" }, {
  headers: { Authorization: `Bearer ${token}` }
});
Interview Q&A
Q: fetch vs axios?
A: fetch is built into browsers, requires manual JSON parsing and manual error-checking (via response.ok), and doesn't reject on HTTP error codes. axios is a library that auto-parses JSON, rejects automatically on error status codes, and supports interceptors and request cancellation more easily.
26Loading & Error StatesMUST KNOW
The standard pattern for any async data-fetching UI: track loading, error, and data as separate states so the UI can respond appropriately at each stage.
function UserList() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    fetch("/api/users")
      .then(res => res.json())
      .then(setUsers)
      .catch(e => setError(e.message))
      .finally(() => setLoading(false));
  }, []);

  if (loading) return <Spinner />;
  if (error) return <p>Error: {error}</p>;
  return <ul>{users.map(u => <li key={u.id}>{u.name}</li>)}</ul>;
}
27Authentication (JWT & Protected Routes)MUST KNOW
A typical React auth flow: user logs in, backend returns a JWT (JSON Web Token), the token is stored client-side and attached to subsequent API requests to prove identity.
Key Points
  • Access Token: short-lived token used to authenticate requests.
  • Refresh Token: longer-lived token used to get a new access token without re-login.
  • Store tokens in localStorage (persists) or sessionStorage (tab-only) — httpOnly cookies are more secure against XSS but need backend support.
async function login(email, password) {
  const res = await axios.post("/api/login", { email, password });
  localStorage.setItem("token", res.data.token);
}

// Attach token to every request
axios.interceptors.request.use(config => {
  const token = localStorage.getItem("token");
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

function logout() { localStorage.removeItem("token"); }
Interview Q&A
Q: Is storing JWT in localStorage safe?
A: It's vulnerable to XSS attacks (any injected script can read localStorage). httpOnly cookies are more secure since JS can't access them directly, but require CSRF protection instead. Many real apps use a mix (short-lived access token in memory, refresh token in httpOnly cookie).

28Why Components Re-renderNEXT
A component re-renders when: its own state changes, its parent re-renders (by default, all children re-render too), its props change, or a subscribed context value changes.
Remember
  • A parent re-rendering re-renders ALL its children by default — even if their props didn't change — unless the child is wrapped in React.memo.
29React.memo, useMemo, useCallbackNEXT
React.memo() is a higher-order component that skips re-rendering a component if its props haven't changed (shallow comparison).
const UserCard = React.memo(function UserCard({ user }) {
  console.log("Rendered:", user.name);
  return <div>{user.name}</div>;
});
// Only re-renders if the `user` prop reference actually changes
Interview Q&A
Q: Why doesn't React.memo always prevent re-renders?
A: It does a shallow comparison of props. If a parent passes a new object/array/function on every render (even with the same values), the reference differs, so memo still re-renders — this is why useMemo/useCallback are often paired with React.memo.
30Lazy Loading & Code SplittingNEXT
Splitting the app's JS bundle into smaller chunks that load on demand rather than all at once, improving initial load time. Done via React.lazy() + Suspense.
import { lazy, Suspense } from "react";

const Dashboard = lazy(() => import("./Dashboard"));

function App() {
  return (
    <Suspense fallback={<Spinner />}>
      <Dashboard />
    </Suspense>
  );
}
31Error BoundariesNEXT
A special class component that catches JavaScript errors anywhere in its child component tree during rendering, logs them, and displays a fallback UI instead of crashing the whole app.
class ErrorBoundary extends React.Component {
  state = { hasError: false };
  static getDerivedStateFromError() { return { hasError: true }; }
  componentDidCatch(error, info) { console.log(error, info); }
  render() {
    if (this.state.hasError) return <h2>Something went wrong.</h2>;
    return this.props.children;
  }
}
// <ErrorBoundary><App /></ErrorBoundary>
Interview Q&A
Q: Can Error Boundaries be written as function components?
A: No — as of now, error boundaries must be class components, since there's no Hook equivalent for getDerivedStateFromError/componentDidCatch.
32Debouncing & ThrottlingNEXT
Debouncing delays execution until a pause in activity (e.g. wait until user stops typing). Throttling limits execution to at most once per fixed interval, regardless of how often the event fires.
function useDebounce(value, delay) {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(timer);
  }, [value, delay]);
  return debounced;
}
// usage: const debouncedSearch = useDebounce(searchTerm, 500);
Interview Q&A
Q: When would you use debouncing in React?
A: Search-as-you-type inputs — to avoid firing an API call on every keystroke, wait until the user pauses typing for e.g. 300-500ms before making the request.
